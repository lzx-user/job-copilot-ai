# 3. 项目后端架构职责

最核心只记：

```text
外部请求
   ↓
Adapter
   ↓
Application
   ↓
Domain
   ↓
Port
   ↓
Adapter
   ↓
数据库 / Supabase / AI
```

## Domain

负责：

> 业务规则是什么。

例如：

```text
一场面试最多 5 轮
completed 面试不能继续提交答案
matchScore 必须在 0～100
```

---

## Application

负责：

> 这件业务应该按照什么顺序执行。

例如：

```text
提交面试回答
↓
检查 Session
↓
读取 Profile / JD
↓
构建 AI Context
↓
调用 AI
↓
保存 Message
↓
更新 Round
↓
返回结果
```

---

## Port

就是接口。

例如：

```go
type AIClient interface {
    AnalyzeJD(...)
    GenerateQuestion(...)
    EvaluateAnswer(...)
}
```

Domain / Application 不需要知道你最后用：

```text
OpenAI
Kimi
DeepSeek
Gemini
```

---

## Adapter

负责连接外部世界。

例如：

```text
OpenAIAdapter
SupabaseAuthAdapter
PostgresRepository
GinHandler
```

---

# 4. 开发原则

不要从架构开始无限设计。

开发顺序：

```text
先确定接口
↓
建立最小目录
↓
实现业务
↓
业务稳定
↓
再抽象
```

如果一个接口目前只需要三个文件，就不要提前建立二十个空文件。

DDD 是为了让业务清楚。

**不是为了目录看起来高级。**

# 9. Go 学习与项目结合

不要专门花一个月“学完 Go 再开发”。

按照：

```text
需要什么
↓
学习什么
↓
马上使用
```

例如：

## 学 struct

马上写：

```go
type InterviewSession struct {
    ID           string
    CurrentRound int
    MaxRounds    int
}
```

## 学 method

马上写：

```go
func (s *InterviewSession) CanContinue() bool {
    return s.CurrentRound < s.MaxRounds
}
```

## 学 interface

马上写：

```go
type AIClient interface {
    AnalyzeJD(ctx context.Context, input AnalyzeInput) (*AnalyzeResult, error)
}
```

## 学 error

马上统一业务错误。

这样学得最快。

# 14. 最重要的原则

```text
先闭环
↓
再工程化
↓
再美化
↓
再扩展
```

不要变成：

```text
学 Go
↓
学 DDD
↓
学六边形
↓
重构目录
↓
继续学习
↓
项目没上线
```

正确方式：

```text
写真实功能
↓
遇到问题
↓
学习 Go / DDD
↓
解决问题
↓
Commit
↓
继续下一功能
```

**每天必须留下一个可以运行的结果。**
