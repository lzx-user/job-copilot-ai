# 项目结构讲解

这份文档按当前真实文件解释项目，适合刚开始学习 Vue 3、TypeScript 和 Go 的开发者。

## 1. 为什么前后端分开

`frontend` 负责浏览器里的页面和交互，`backend` 负责服务器接口。分开后，浏览器不会直接接触后端私密配置，页面和 API 也可以独立构建、部署。

## 2. 从启动开始看

- `package.json` 是项目说明和命令清单，依赖安装后会生成 `node_modules`；
- `vite` 是前端开发服务器和构建工具；
- `main.ts` 创建 Vue 应用、注册 Pinia、Router、Element Plus，等待首次 Session 检查后挂载；
- `App.vue` 是最外层组件，当前只负责显示 `RouterView`；
- `index.html` 是浏览器最先打开的 HTML。

后端从 `backend/cmd/server/main.go` 启动。入口加载 `internal/config`，创建 Gin Router，再监听 `APP_PORT`。`internal/adapter/http` 负责 Router、Handler 和 CORS Middleware，`pkg/response` 负责统一 JSON。

业务代码按轻量 DDD 和六边形架构组织：`internal/domain/analysis` 保存 JD 分析实体与分数范围等业务规则，`internal/application/analysis` 编排分析用例，`internal/port` 定义 AI、认证和仓储所需的最小接口，`internal/adapter` 连接 Gin、Supabase 和后续的 LLM、PostgreSQL。尚未实现的业务不会预先创建空目录。

JD API 调用链是：Gin Router 先用 Supabase 校验 Bearer Token，Handler 将 JSON 转为 Command，Application 组织用例，Domain 校验岗位与候选人输入，最后通过 AI Port 调用 OpenAI 兼容 Adapter。8.22 已补齐八字段 Prompt、严格 JSON 解码和业务字段校验；数据库保存仍属于后续阶段。

## 3. Vue 页面如何显示

Vue 组件通常由模板、`<script setup lang="ts">` 和样式组成。`views` 是路由页面，`components` 是可以复用的局部组件。`AppLayout.vue` 是所有 `/app/**` 页共享的父布局，所以侧栏和顶栏不会随着页面切换重建。

## 4. Router 和守卫

`src/router/index.ts` 用懒加载减少首屏体积。进入 `/app/**` 前，守卫先等待 `authStore.initialize()`，再检查真实 Supabase Session；未登录就转到登录页。登录页和注册页标记为 `guestOnly`，已登录用户访问时会回到仪表盘。

## 5. Pinia、state 和 action

Pinia store 是跨页面共享的响应式状态。`auth.store.ts` 的 state 保存 session、user、loading 和错误；action 负责登录、注册、初始化和退出等异步操作。`ui.store.ts` 只保存侧栏收起和移动端抽屉状态。

Session 表示本次登录有效期与用户身份，User 是用户资料。刷新时 Supabase 从持久化存储恢复 Session；`onAuthStateChange` 监听其他标签页的登录变化。监听器在重新注册前会取消旧订阅，避免重复触发。

## 6. Axios 和 health 流程

`src/api/request.ts` 集中设置后端 baseURL、JSON 请求头和超时。`health.api.ts` 调用 `/health`，登录页只把结果显示为“检查中 / 服务正常 / 暂时无法连接”，不会让健康检查破坏登录主流程。

完整过程是：浏览器调用 `http://localhost:8080/api/v1/health` → Gin 经过 CORS Middleware → Router 匹配 `handler.Health` → `response.Success` 组装统一 JSON → 前端读取 `data.status`。

## 7. Supabase 登录过程

`lib/supabase.ts` 读取 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`。缺少配置时导出 `null`，页面显示明确提示而不是白屏。配置存在时，用户提交表单 → `authStore` 调用 Supabase → Supabase 返回 Session → store 更新 → Router 守卫允许进入 `/app/dashboard`。

anon key 可以出现在前端，因为它不是管理员密钥；但所有业务表仍必须开启 RLS。service role key 会绕过 RLS，绝对不能放浏览器。

## 8. `.env` 与 `.env.example`

`.env.example` 只写变量名称和安全的本地默认值，应该提交；`.env`、`.env.local` 写真实配置，不应提交。Vite 只把 `VITE_` 前缀变量暴露给前端。

## 9. 修改页面从哪里开始

先看 `src/views/` 找对应页面，再看 `AppLayout.vue` 是否需要公共变化；颜色、间距和圆角先查 `src/styles/variables.css`。需要跨页面共享的登录状态才放 Pinia，不要把每个输入框都放进 store。

## 10. 当前为什么业务页仍以静态骨架为主

当前已经完成 Go 后端基础迁移，但 JD、档案、历史和面试的数据闭环尚未实现。页面继续使用空状态表达真实边界，避免用演示数据冒充数据库或 AI 已接入。
